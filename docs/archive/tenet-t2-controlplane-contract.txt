make the agent layer live. Concretely:

1. New package `control_plane/` with a FastAPI app (app factory + `uvicorn control_plane.app:app`)
   that is the single user-facing runtime:
   GET  /health            -> {status: LIVE|DEGRADED|DEMO, mode, provider, model, commit, uptime}
   GET  /api/overview      -> counters + authority summary (from the kernel)
   GET  /api/activity      -> newest-first events, ?limit=
   GET  /api/actions       -> all actions
   GET  /api/actions/pending
   GET  /api/actions/{id}  -> one action with its decision, receipt, upstream_contacted
   GET  /api/agents        -> agents with authority state
   GET  /api/warrants      -> warrants with lifecycle state
   POST /api/actions/{id}/approve
   POST /api/actions/{id}/deny
   POST /api/agents/{id}/revoke
   POST /api/ask           -> executes the REAL orchestrator (below)
   Keep GET / serving the Control Room page (the repository's existing index.html dashboard,
   TENET branding) and keep /api/state as a compatibility alias if the page uses it.
2. The service imports the ENFORCEMENT KERNEL from the mirrored package in this repository
   (`node/warrnt`, added to sys.path at import time - the mirror is shipped with the submission)
   and delegates every decision to it. The control plane may read kernel state and call kernel
   decision functions; it may NEVER decide, allow, or contact an upstream tool by itself.
   If the kernel cannot produce a decision, the control plane must refuse (HTTP 503 for the
   decision endpoints, a refusal body for /api/ask) - never a silent allow.
3. Provider seam in `control_room/agents.py`: configure the OpenAI Agents SDK against an
   OpenAI-compatible DeepSeek client built explicitly at runtime:
   base_url `https://api.deepseek.com`, model `deepseek-chat`, key read from env
   `DEEPSEEK_API_KEY` (by name only). No code path may require `OPENAI_API_KEY`. Provider
   failure must degrade, not crash: `/health` reports DEGRADED and `/api/ask` returns a refusal
   with the reason. Never print, log, echo or return the key; add a test asserting the key string
   never appears in any response body.
4. Orchestrator: exactly four agents - TENET Orchestrator plus the three specialists
   (Governance, Kernel, Control-Plane) used as tools. Specialist answers are grounded in kernel
   calls (tool results), never in model invention. `/api/ask` returns
   `{run_id, answer, evidence[], specialists[], next_action}`; `evidence[]` entries carry the
   kernel facts they came from (action id, warrant id, decision, receipt id) with real ids only.
   No chain-of-thought in the response.
5. Correlation: every `/api/ask` run records `run_id` and, when it results in or references an
   action, the `action_id`; both traces must be retrievable (`/api/activity` entries carry both
   when applicable). Agent trace and security trace stay separate records that share ids.
6. Activity must be real: the current DEMO FEED (fixture events rendered as if live) must not be
   the production path. Put fixtures behind an explicit mode flag `TENET_MODE=demo` (default
   `live`), so a running production instance shows only kernel events, and the page/API label the
   mode. `/health` must make LIVE vs DEMO unmistakable.
7. Tests (pytest, no network): each route's status and shape; approval flow (pending -> approve ->
   allow, receipt present); deny flow; revoke expires a pending action; fail-closed when the
   provider is unreachable (simulate by clearing the key env / raising in the client) and when the
   kernel raises; mode flag behaviour; no-secret-leak test.
8. A runnable local proof: `scripts/tenet_live_proof.py` that starts (or targets) the app, performs
   one full chain - user question -> orchestrator -> specialist -> tool -> kernel decision ->
   execution or refusal -> receipt - and prints ONE JSON line with run_id, action_id, decision,
   upstream_contacted, receipt_id, answer. It must fail loudly (non-zero exit) if any id is
   missing or if `upstream_contacted` is true without an allow decision.
